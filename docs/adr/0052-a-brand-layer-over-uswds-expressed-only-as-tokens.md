# ADR-0052 — A brand layer over USWDS, expressed only as tokens

- **Status:** Accepted
- **Date:** 2026-08-05
- **Context:** Session 30, workstream C task C1
- **Builds on:** [ADR-0011](0011-astro-uswds-frontend-at-app.md) (USWDS is the chassis),
  [ADR-0027](0027-light-by-default-dark-by-choice.md) (two themes, chosen at runtime),
  [ADR-0042](0042-contrast-is-computed-from-the-tokens.md) (the palette is checked by computing it)

## Context

The reader wore USWDS's defaults: Public Sans by way of the system stack, Georgia for statutory
text, USWDS blue for links, and cool greys. That reads as an agency site, which this is not. It is
also not a decision anyone made — it is what was left after ADR-0011 chose the chassis.

The constraint is that USWDS stays. No second CSS framework, no utility-class layer, no client
runtime. Whatever the site looks like has to be reachable from the theme settings USWDS already
exposes and the custom properties the reader already declares, because that is what makes the next
page inherit the design for free.

## Decision

The brand is design-token overrides and nothing else.

**Type.** Spectral for statutory text, Archivo for the interface, the system stack for monospace.
Both are served from this origin as Latin-subset WOFF2 out of `frontend/public/fonts`, built by
`scripts/fonts.py` from pinned commits in `google/fonts` and recorded in
`docs/verification/fonts.json` — upstream URL and sha256 in, byte size and sha256 out. Nothing on a
reader page fetches type from another host, so `font-src 'self'` in ADR-0030's CSP stays true and
the first paint of a provision costs no round trip to somebody else's server.

The `@font-face` rules are written out in `site.scss` rather than generated by USWDS. USWDS emits
one rule per static weight from a map of filenames, which cannot express a variable face's weight
range, and hard-codes `font-display: fallback` — a block period during which the text of the Code is
not on screen. These declare `swap`.

**Colour.** One palette, two themes, in `site.scss`'s token blocks and in the USWDS settings beside
them so that USWDS's own components and the reader's paint from the same values. Indigo `#31509d`
for links and emphasis; `#90302e` for errors and repeals; `--version` `#036639` for version
semantics and for nothing else; amber for the highlighted provision. Every pair is in
`docs/verification/contrast.json` — 20 pairs, 40 checks, 0 failures, and `--version` was added to
that list rather than left to look about right.

**Measure.** `--measure` and `--measure-wide`, replacing the `46rem` that was written out in five
rules. 42rem, which is a median 68 characters of Spectral at the reading size.

### What is a token change, and what is not

Task C1 asked for the audit before the override. Of the proposal in `claude-code/assets/brand.md`:

| Proposed | Landed here | Why |
| --- | --- | --- |
| Two typefaces, self-hosted | yes | `$theme-typeface-tokens` plus six `@font-face` rules |
| Indigo primary, warm neutrals, reserved green | yes | USWDS colour settings + custom properties |
| A fixed reading measure | yes | `--measure`, and the five rules that used to spell it out |
| `text-wrap: pretty`, no justification | no | a rule on the prose container, not a token — C3 |
| The subsection ladder as one indentation scale with hanging numbers | no | markup and layout — C3 |
| A print stylesheet | no | a whole stylesheet — C3 |
| Quoted amending text, notes and source credit visually distinguished | no | per-element rules — C3 |
| A wordmark | no | markup in `SiteHeader` — C2 |
| Every component documented on `/app/design` | no | a page — C2 |

One rule that is not a token changed anyway, and is called out because it is exactly the kind of
thing a token audit cannot see: `.soon__tag` carried `opacity: 0.85` over `--muted`, which is 4.4:1
against the 4.5 the same colour passes at on its own. A translucent text colour has a contrast ratio
that exists only in the browser, so `scripts/contrast.py` reads the token as passing and the axe
scan is the only thing that can say otherwise. The opacity is gone.

## What was measured

- **Fonts.** Six files, 125,720 bytes; 45,872 of that preloaded (the two roman faces). Reproducible:
  `uv run --with "fonttools[woff]" python scripts/fonts.py` twice gives byte-identical output, which
  it did not until the instancer was told to stop stamping the clock into `head.modified`.
- **Cap heights.** 343 for Archivo, 330 for Spectral, read out of the binaries. USWDS normalises its
  whole type scale against this number, and its unit — cap height in px at a 500px font size — is
  documented nowhere; it was recovered from the two faces USWDS ships whose declared values match
  their files (Public Sans 361.5→362, Merriweather 371.5→371; its Source Sans Pro and Roboto Mono
  values do not match theirs).
- **Measure.** `frontend/scripts/measure.mjs` counts characters per rendered line by measuring each
  character and bucketing by line box, at 375, 768 and 1280 CSS px →
  `docs/verification/measure.json`. 46rem held a median 82 characters. 42rem holds 68, p10–p90
  62–73. At 375 the viewport is the constraint and the column holds 38.
- **Contrast.** 20 pairs × 2 themes, 0 failures (`uv run python scripts/contrast.py`).
- **Accessibility.** 258 axe scans, 8 violation/route pairs over 1,794 nodes — the same eight
  ADR-0039 already owns, no new ones.
- **JavaScript.** Unchanged. `docs/verification/js-bytes.json` is byte-identical; this task adds no
  script.
- **Reflow.** `make shots` at 320, 375, 1280 and 1280-at-200% — no new horizontal scroll.

## Costs

**Two typefaces on the critical path.** 44.8 KB preloaded, 122.8 KB if a page reaches every face.
`font-display: swap` means the fallback stack paints first and the page reflows when the webfonts
arrive, which is a visible shift on a slow link — the price of not having a blocking period.

**The measure costs scroll length on wide screens.** 16 U.S.C. § 45f at 1280px went 8,829px to
9,117px, +3.3%; § 1801 went 25,365 to 26,312, +3.7%. At 375px nothing moved, because the viewport
is narrower than either measure there.

The cost that was anticipated did not occur, and the measurement is worth stating in three parts
because the prediction was that the *face* would lengthen the page. Georgia at 46rem, Spectral at
46rem and Spectral at 42rem, all at 1280px, same container rebuilt three times:

| | § 45f | § 470a | § 1801 |
| --- | --- | --- | --- |
| Georgia, 46rem | 8,829 | 1,448 | 25,365 |
| Spectral, 46rem | 8,798 | 1,418 | 25,245 |
| Spectral, 42rem | 9,117 | 1,442 | 26,312 |

The face swap alone made every page slightly *shorter*, and left the line length identical at a
median 82 characters. All of the added scroll is the narrower column.

Only the last row is in `docs/verification/measure.json`, which records the site as it stands. The
other two are the same `make measure` run against the parent commit and against an intermediate
state, and are reproducible by checking those out.

**The neutral ramp is USWDS's `gray-warm`, not the palette's own.** USWDS derives a component's text
colour from its background (`get-color-token-from-bg`, used by the table, the summary box, the
alert) and that function needs a palette token *by name*; handed a hex it returns one, and the
`color()` call downstream fails the compile. So the neutrals are named USWDS tokens and the reader's
neutral custom properties take their values from those, rather than the oklch ramp `brand.md`
proposed. The hues — indigo, red, green, amber — go through `set-theme-color`, which does take a
hex, and are the proposal's.

**The focus ring is still USWDS blue.** The brand assigns focus to the primary indigo.
`$theme-focus-color` is one compile-time Sass value and the theme is chosen at runtime, and
`#31509d` is 2.4:1 on the dark page — below the 3:1 SC 1.4.11 asks of a focus indicator. A per-theme
focus colour is a rule rather than a setting, and belongs to C2.

**Spectral is four files, not one.** `ofl/spectral/METADATA.pb` declares fourteen static instances
and no axes, so roman, italic, bold and bold-italic are four downloads where Archivo is one per
style. All four are reachable from statutory text: `<i>` and `<b>` are both in `uslm.ts`'s inline
vocabulary.

**No condensed Archivo.** The `wdth` axis is pinned to 100 and dropped. `brand.md` wants the
condensed cut for release-point labels such as `119-102not101`; whoever wants it will have to
re-run `scripts/fonts.py` without the pin and pay the bytes.

**Green and red do not yet mean only "changed".** `/app/docs` paints its method badges green for
POST and red for DELETE (`.endpoint__method--post`, `--delete`), which is the discipline this ADR
states, broken on one page. Left alone here rather than restyled in a token commit.

**Two colour values are still literals.** The redline's insertion and deletion washes, and the
highlight wash, are `rgba()` — a translucent fill is not a token, and `color-mix()` would degrade to
no wash at all on a browser that lacks it. They are written from `--version`, `--danger` and the
amber, and will drift from them if one is changed alone.

## Alternatives considered

**Let USWDS generate the `@font-face` rules** via `$theme-font-serif-custom-src`. It cannot express
a variable font, and its `font-display: fallback` is not configurable.

**Keep Public Sans and Merriweather.** They are the federal voice by design. Borrowing them makes a
prototype look like an official publication of the United States, which is a claim this site should
not make.

**Adopt the proposal's oklch neutrals as hex.** Fails the compile, as above.

**Leave the measure at 46rem and change only the face.** The face swap alone changes neither the
line length nor the page height, so the brand's measure would have been a token nothing acted on.
